# LOCR 全卡卡面 · 2026-10-08

当前完成日版 LOCR 的 80 种卡、318 个罕贵度/版式组合。双击根目录 `全卡图鉴.cmd` 会自动准备预览服务并打开图鉴。入口为
`http://127.0.0.1:5173/public/locr-catalog/index.html`，工艺审查页顶部也有入口。

本次沿用 `src/scene/material-finishes.js` 已接受的工艺，不修改镜碎膜的坐标、方向或光位响应。

## 插画核对及补正

官方产品数据库给出的 JP029～038 插画索引不是默认插画：JP029、030、032、035～038 为第二插画，
JP031、033、034 为第三插画。之前仅按卡片密码取图，因此这十张需要补取异画。

本轮使用同一浏览会话取得官方图片，作为核对参考；使用独立 SIFT 特征/单应性匹配核对全部80种，
每种至少12个内点。十张异画实测有91～163个内点。运行素材全部来自用户本地无 SAMPLE 图库，
官方带 SAMPLE 图只用于核对，不参与生成。

- 核对来源、图像与记录：`test-results/locr-full-cards/official-art-reference-verified/`、
  `official-art-reference.json`、`artwork-audit-verified.json`。
- 前一次跨会话取得的图片为 Coming Soon 占位图，保留在 `official-art-reference/`，不作为有效证据；
  `artwork-audit.json` 同样无效。有效证据以带 `verified` 的文件和目录为准。
- 十张正确异画已补入用户 LOCR 目录；此前十张旧插画保留，所以文件夹当前有108张 JPG，
  完整卡池实际引用98张。对照表及规格文件已同步正确的98张。
- 图片编号和实际卡片密码分开处理：出框图、异画图的偏移编号不印为卡片密码；生成底图使用原密码及正确的 LOCR-JP 卡号。

## 卡面处理

所有底图按物理卡面比例59:86输出，保留插画构图和原日文效果文本。
卡名按官方名称以 Windows Yu Gothic 重新排印，原读音区域保留；它是可用的数字卡面，
不是逐字复制原厂字体的印刷分色文件。SR卡名保持普通印字，深色框和魔陷使用浅色印字。
星数/阶级、属性及魔陷圆标按每张卡的数据生成遮罩，并以局部图像检查位置。

UL/CR浮雕纹理在生成阶段固定，效果文本保持平整；PSER外缘和实际可见内框使用中性金属底色。
出框内框遮罩仅保留源图上可见的金色框段，避免盖住跨框主体。
GMR使用既有实物校准模板的外缘纹样、厚箔、专用框线；`001/100`是工艺展示序号，未分配玩家实体编号。

```powershell
python tests/locr-catalog.py
npm run test:ui -- locr-catalog
npm run test:ui -- material-review
npm run check
npm run format:check
```

生成器保留十张旧插画和修正前对照表，不删除用户素材。

剩余出框/GMR的渲染、深色框SR印字、圆标遮罩，以及桌面/手机图鉴布局。
验证结果：静态资源检查、全卡浏览器检查、原27张工艺审查、源码引用检查和格式检查全部通过。
全卡浏览器实测贴图数峰值23，无缺失资源、脚本错误或外部运行请求。
